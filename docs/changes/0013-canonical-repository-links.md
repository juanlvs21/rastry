# Change 0013: Canonical repository links

Status: Implemented

## Context

The public site still referenced the previous GitHub owner in content and generated links. GitHub actions were also inconsistent: some links opened in the current tab while others were generated by Starlight.

## Change

Point all Rastry GitHub links to `juanlvs21/rastry` and make repository links open in a new tab with safe `noopener noreferrer` behavior. The Starlight social icon uses the same behavior as the custom site navigation and source buttons.

## Scope

- Web site navigation, buttons, source links, release links, and repository-backed pages.
- Starlight documentation and preset content links.
- The canonical repository URL used by metadata and generated pages.

## Acceptance criteria

- No public Rastry link points to the previous GitHub repository owner.
- GitHub links rendered by the web site use `target="_blank"` and a safe `rel` value.
- The web site builds successfully.

## Consequences

Repository navigation leaves the Rastry site or documentation page open, preserving the reader's current context.

## Alternatives considered

- Updating only the visible home buttons: rejected because source links and generated documentation links would remain stale.
- Relying on browser defaults for external links: rejected because the behavior would be inconsistent and less explicit.

## Implementation plan

1. Replace the repository base URL and static GitHub references.
2. Add explicit external-link attributes to generated and authored GitHub anchors.
3. Override Starlight's social icon component to keep the header behavior consistent.
4. Build and run repository checks.

## Verification

- `bun run build:web`
- `bun run check`
- Repository-wide search for the previous GitHub owner.

## Follow-up

Keep future repository links derived from the shared `repositoryUrl` constant where possible.
